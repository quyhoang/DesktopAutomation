A programmable logic controller, or PLC, has a built-in microcomputer (central processing unit (CPU)) and memory (storage element).
These useful devices operate with external input devices (push button switches and limit switches) that are mounted on the operating panel or system and allow you to freely control external output devices, such as indicator lights and solenoids.
Programs are written into the PLC memory from a computer installed that has dedicated ladder programming software installed.

https://www.electronics-tutorials.ws/blog/relay-switch-circuit.html

A Programmable Logic Controller is a rugged industrial computer that reads inputs (buttons, sensors), runs your program, and drives outputs (motors, valves, lights). It's built to run for years without rebooting and to survive heat, vibration and electrical noise.

The scan cycle

A PLC doesn't run your program once and stop. It repeats the same loop continuously:

Read inputs: take a snapshot of every input.
Execute program: run your logic top to bottom using that snapshot.
Write outputs: update all the physical outputs at once.
Housekeeping: communications and diagnostics, then back to step 1.

One loop takes roughly 1 to 20 ms, and that is called the scan time.

Why this matters: because inputs are a snapshot, an input can't change halfway through your program. This keeps the logic predictable.

Two vertical power rails (left and right) have rungs between them. Each rung has conditions on the left (contacts) and an action on the right (a coil).

Power flows left to right. If a path of closed contacts connects the left rail to the coil, the coil turns ON. The PLC evaluates this with logic, not real current.

Ladder shows only the instruction symbols. A physical button's type doesn't change the ladder symbol. The wiring determines the bit value, and you then choose the instruction that tests it. Allen-Bradley calls the ] [ instruction XIC (Examine If Closed) and the ]/[ instruction XIO (Examine If Open).

In a real PLC, an input bit is set by voltage at the input terminal. Supplying 24 V to the terminal sets the corresponding memory bit to 1, and 0 V clears it to 0.

Seal-in (latching)
The problem: a Start button is momentary. As soon as you release it, its bit goes back to 0, so the rung would go false and the motor would stop.

The solution: put a contact of the output's own bit in parallel with Start. This is where the parallel symbol comes in.

The standard stop-button example shows how this works. A stop button is wired NC, so at rest it passes 24 V and the input bit is 1. You then program a ] [ instruction, which passes when the bit is 1. If you press the button or a wire breaks, the input drops to 0, the rung goes false, and the motor stops. This is fail-safe.

Note that this is different from what many beginners assume, which is an NO stop button with a ]/[ instruction.

Logical or physical? The seal-in contact is logical (virtual). None of the contacts or coils in a ladder program are real. They are read and write operations on bits in PLC memory.

Input or output? A contact is neither. A contact only reads a bit, and it can read any bit: an input, an output, or an internal bit. In the seal-in, it reads the output's bit.

"Same scan" and how it fits with the snapshot

You're right to challenge that. My Lesson 1 description was too simplified, and the full picture has two kinds of data.

1. Physical I/O is frozen for the whole scan.

Input terminals are copied into an input image at the start of the scan, and that image doesn't change during the scan.
Output terminals are only updated from the output image at the end of the scan, all at once.
So if a sensor changes mid-scan, the program doesn't see it until the next scan. This part of your understanding is correct.

2. Internal bits (and the output image) update immediately.

When a rung's coil executes, it writes its bit right then.
Any rung evaluated later in the same scan sees the new value.
Rungs evaluated earlier still see the old value until the next scan.

So the program is not "read everything, then update everything". Only the physical inputs and physical output terminals work that way.
